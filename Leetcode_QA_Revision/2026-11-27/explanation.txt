Title: Maximum Number of Items From Sale I
URL: https://leetcode.com/problems/maximum-number-of-items-from-sale-i/

LLM Explanation:
Buying an item for the first time pays its price and gives one copy of it plus one free copy of every other item whose factor is a multiple of its factor. So the first copy of item i is worth 1 + g_i, where g_i is the number of j != i with factor_j % factor_i == 0. Any additional copy of any item is worth exactly 1, so extra spending is best put on the cheapest item (price pmin). Free copies are counted only once per bought item type, so extra copies never add bonuses.

This is a knapsack. Each item is a 0/1 choice with weight price_i and value 1 + g_i. After that, an unbounded item of weight pmin and value 1 models the extra copies. A dp solution may use an unbounded copy without the 0/1 bonus, which only undercounts and never exceeds a real purchase plan, so the maximum is correct. Every real plan, meaning a set of first copies plus extra copies, is representable, because any extra copy can be swapped for a cheapest-item copy at no greater cost.

Time complexity: O(n^2 + n * budget), about 2.5 million operations at most. Space complexity: O(budget).

Edge cases:
- Duplicate factors count as free copies for each other, since only j != i is required.
- An item priced above the budget never enters the 0/1 loop.
- If no item has any multiple, the answer is the cheapest-item count, budget // pmin or better via the knapsack.
- n=1 gives g=0, so the answer is budget // price.
