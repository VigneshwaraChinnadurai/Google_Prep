Title: Maximum Number of Non-Overlapping Substrings
URL: https://leetcode.com/problems/maximum-number-of-non-overlapping-substrings/

LLM Explanation:
APPROACH: Greedy interval scheduling sorted by right endpoint — O(n).

STEP 1: For each character c, record first[c] and last[c].

STEP 2: For each valid starting position i (first[s[i]] == i), compute the
minimal valid right boundary via get_right(i):
  - Start with r = last[s[i]].
  - Expand: for every char encountered in s[i..r], if its first occurrence is
    before i → invalid (return -1). Otherwise extend r = max(r, last[char]).
  - This finds the tightest valid interval starting at i.

STEP 3: Sort valid intervals by right endpoint. Apply greedy:
  - If new interval starts after last_end: add it (new non-overlapping substring).
  - If new interval overlaps but ends earlier: replace last result (same count,
    shorter total length — the unique minimum-length solution).
  - If overlaps and ends later: skip.

WHY SORT BY RIGHT: Standard greedy for maximum non-overlapping intervals. Sorting
by right endpoint ensures we always take the earliest-ending valid interval,
maximising future choices.

WHY REPLACE WORKS: Among overlapping intervals where the new one ends earlier,
it must start later (since intervals share a prefix range), so replacing gives
a strictly smaller substring with same count.

COMPLEXITY: O(n) for preprocessing + O(n) for get_right (total across all calls,
amortized) + O(k log k) sorting (k ≤ 26 distinct chars × valid intervals) = O(n).

get_right(8): r=10. j=8,9,10:'c',first=8>=8✓. r=10. → (8,10)

intervals=[(0,7),(2,2),(3,3),(8,10)]. Sort by r: (2,2),(3,3),(0,7),(8,10).

Process:
