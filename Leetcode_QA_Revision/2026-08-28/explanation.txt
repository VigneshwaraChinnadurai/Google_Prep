Title: Lexicographically Smallest Palindromic Permutation Greater Than Target
URL: https://leetcode.com/problems/lexicographically-smallest-palindromic-permutation-greater-than-target/

LLM Explanation:
**Optimized Algorithm:**
Instead of exploring all permutations, use a greedy "next permutation" approach:

1. **Validate palindrome feasibility** using character frequencies

2. **Greedy construction:**
   - For each position i in the first half:
     - Match target characters for positions 0 to i-1
     - At position i, try placing characters strictly greater than target[i]
     - Fill remaining positions with smallest available characters
     - Build palindrome and return immediately if valid

3. **Why it works:**
   - By iterating i from 0 to half_len, we find the leftmost position where we can increment
   - Placing smallest chars after gives the lexicographically smallest result
   - Greedy matching before increment preserves this property

**Complexity:**
- Time: O(n²) - at most n positions × n characters to try
- Space: O(n) for character counts and result

**Key Optimization:**
Avoids recursive backtracking entirely by constructing directly. At most we try n different positions × n different characters, making it polynomial instead of exponential.

LLM Testcase Validation:

- i=0: Try ch>'a' → ch='b', fill_smallest([a:1], 1)=['a'] → "ba" + mirror → "baab" > "abba" ✓

- i=1: Match 'b' at pos 0, try ch>'b' at pos 1 → none available
- i=2: All matched, "bbaa" > "bbaa"? No
- Expected: "" ✓

Test Case 3: s="abc", target="abb"
- odd_count=3, n=3 requires odd_count==1 → return "" ✓

- i=0: Try ch>'a' → none from half_counts
- i=1: Match 'a' at pos 0, "a" + "c" + "a" = "aca" > "abb" ✓
