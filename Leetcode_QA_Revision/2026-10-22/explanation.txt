Title: Minimum Operations to Sort a Permutation
URL: https://leetcode.com/problems/minimum-operations-to-sort-a-permutation/

LLM Explanation:
Both operations preserve the cyclic order of the array, up to direction. Rotation keeps the cyclic sequence and reverse flips its direction. The sorted array is 0,1,...,n-1 in cyclic order, so nums is solvable only if it is a rotation of the ascending sequence or of the descending sequence. Anything else returns -1.

Ascending rotation with nums[0]=k:
- If k=0 it is already sorted, so the answer is 0.
- Otherwise we can rotate left n-k times.
- Or we can do reverse, rotate left m, reverse. Since R·L^m·R equals a right rotation by m, this costs k+2.
- Using more reverses never helps, so the answer is min(n-k, k+2).

Descending rotation with nums[0]=k (the reverse count must be odd):
- Rotate left (k+1)%n times to bring n-1 to the front, then reverse once. The cost is (k+1)%n+1.
- Or reverse once, which gives an ascending rotation starting at (k+1)%n, then rotate left (n-k-1)%n times. The cost is 1+(n-k-1)%n.
- Take the smaller of the two.

When both patterns hold (n<=2), take the minimum of both cases.

Time complexity: O(n). Space complexity: O(1).

Edge cases:
- n=1 gives 0.
- n=2 is handled by the both-patterns rule.
- An already sorted array gives 0.
- A non-rotation permutation gives -1.
