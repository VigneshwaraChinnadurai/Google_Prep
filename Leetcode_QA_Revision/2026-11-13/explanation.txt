Title: Count Non-Decreasing Subarrays After K Operations
URL: https://leetcode.com/problems/count-non-decreasing-subarrays-after-k-operations/

LLM Explanation:
For a fixed subarray [l..r], the minimum number of operations to make it non-decreasing is the sum over i of (prefixMax(l..i) - nums[i]). Extending the window to the left only increases that cost, so for each l there is a largest r that stays within k, and this largest r never increases as l moves left. That gives a two-pointer sweep with l going from n-1 down to 0 and r only shrinking.

The window's prefix-maximum structure is kept as a deque of segments [value, start, end], each covering a run of indices with the same prefix maximum, with the leftmost segment at the front. The cost is sum(value * length) - windowSum, and windowSum comes from prefix sums.
- Adding l: pop front segments whose value is <= nums[l] and merge them into a new front segment of value nums[l]. This is amortized O(1), since each segment is created once and popped once.
- Shrinking r: shorten the back segment by one index (and pop it if it becomes empty), subtract its value from the running total, and decrement r. Each window is valid at r = l, since a single element costs 0.
- Each l contributes r - l + 1 valid subarrays.

Time complexity: O(n), since every segment and every r step is handled a constant number of times. Space complexity: O(n).

Edge cases:
- n=1 returns 1.
- An already non-decreasing array returns n*(n+1)/2, since the cost is always 0.
- A strictly decreasing array with a small k limits each l to short windows.
- Values reach about 1e9 times 1e5, which Python integers handle without overflow.
