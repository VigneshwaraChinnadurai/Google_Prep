Title: Palindromic Path Queries in a Tree
URL: https://leetcode.com/problems/palindromic-path-queries-in-a-tree/

LLM Explanation:
A path can be rearranged into a palindrome exactly when at most one letter appears an odd number of times. Store each path's letter parities as a 26-bit XOR mask, so the check is mask & (mask - 1) == 0.

Let P[v] be the XOR mask from the root to v. For a query (u, v), the path mask is P[u] ^ P[v] ^ bit(char of lca(u, v)). XORing P[u] and P[v] cancels the LCA and everything above it, so the LCA's own letter is added back once.

For updates, changing node u's letter flips P[w] by (old_bit ^ new_bit) for every w in u's subtree. A preorder numbering makes each subtree a contiguous range, so a Fenwick tree with range XOR update and point query handles this: add x at tin[u] and at tin[u]+size[u], and P[w] = base[w] ^ prefix_xor(tin[w]). LCA uses binary lifting. The DFS is iterative to avoid recursion limits when n = 5*10^4.

Time complexity: O((n + q) log n). Space complexity: O(n log n) for the lifting table.

Edge cases:
- n=1: the query (0, 0) gives a single-letter mask, so true.
- u == v: the LCA is u, and the mask reduces to that one node's letter.
- An update to the same letter is skipped.
- The LCA letter uses the current letter of the LCA node, which stays correct after updates.
- When u is an ancestor of v, the formula still works because the LCA's letter is added back once.

LLM Testcase Validation:
Test 1: n=3, path 0-1-2, s="aac". "query 0 2": the LCA is 0, and the path mask is a^a^c = {c}, a single bit, so true. "update 1 b" changes node 1 to b, and the subtree of 1 (nodes 1 and 2) gets XORed with a^b. "query 0 2": the path is abc, three odd-count letters, so false. Output [true, false]. Expected [true, false]. PASS
Test 2: n=4, star centered at 0, s="abca". "query 1 2": LCA is 0, the mask has a, b and c set, so false. "update 0 b" gives s=bbca. "query 2 3": the path is c, b, a, three odd counts, so false. "update 3 a" changes nothing. "query 1 3": the path is b, b, a, mask is {a}, so true. Output [false, false, true]. Expected [false, false, true]. PASS
