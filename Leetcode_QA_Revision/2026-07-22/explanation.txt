Title: Maximize Active Section with Trade II

LLM Explanation:
The user wants me to solve the LeetCode problem "Maximize Active Section with Trade II".

Here's a breakdown of the problem:

**Input:**
- `s`: A binary string of length `n`. '1' is active, '0' is inactive.
- `queries`: A list of pairs `[l, r]`, each representing a substring `s[l...r]`.

**For each query `[l, r]`:**
1.  **Isolate the substring:** Take `sub = s[l...r]`.
2.  **Augment:** Create a new temporary string `t = '1' + sub + '1'`.
3.  **Perform a trade (at most once):**
    - **Step 1 (Sell):** Find a contiguous block of '1's in `t` that is surrounded by '0's. This means a pattern `...01...10...`. Convert this block of '1's to '0's.
    - **Step 2 (Buy):** Find a contiguous block of '0's in `t` that is surrounded by '1's. This means a pattern `...10...01...`. Convert this block of '0's to all '1's.
4.  **Goal:** The trade should be chosen to maximize the final number of '1's in the substring `s[l...r]` part of `t`.
5.  **Calculate result:** Count the number of '1's in the modified `s[l...r]` part. The augmented '1's don't count.
6.  **Independence:** Each query is independent. The original string `s` is not modified.

**Output:**
- An array `answer` where `answer[i]` is the result for `queries[i]`.

**Let's analyze the trade operation:**

- **Sell:** We need to find a block `t[i...j]` of '1's where `t[i-1] == '0'` and `t[j+1] == '0'`. Let the length of this block be `len_1 = j - i + 1`. After converting it to '0's, we lose `len_1` active sections.
- **Buy:** We need to find a block `t[p...q]` of '0's where `t[p-1] == '1'` and `t[q+1] == '1'`. Let the length of this block be `len_0 = q - p + 1`. After converting it to '1's, we gain `len_0` active sections.

The net change in the number of '1's is `len_0 - len_1`. To maximize the final count, we need to maximize this net change.

So, for a given query `[l, r]`, the task is to:
1.  Find the initial number of '1's in `s[l...r]`. Let's call this `initial_ones`.
2.  Find the best possible trade within the augmented string `t = '1' + s[l...r] + '1'`.
3.  The best trade corresponds to maximizing `len_0 - len_1`.
    - We need to find the maximum length of a block of '0's surrounded by '1's in `t`. Let this be `max_len_0`.
    - We need to find the minimum length of a block of '1's surrounded by '0's in `t`. Let this be `min_len_1`.
4.  The maximum net gain is `max_len_0 - min_len_1`.
5.  The final answer for the query is `initial_ones + max(0, max_len_0 - min_len_1)`. We take `max(0, ...)` because if no valid trade is possible, or if the best trade results in a loss, we simply don't perform the trade.

**What constitutes a "valid trade"?**
A trade is valid if we can perform both the "sell" and "buy" steps.
- A "sell" is possible if there exists at least one block of '1's surrounded by '0's in `t`.
- A "buy" is possible if there exists at least one block of '0's surrounded by '1's in `t`.

If either of these is not possible, no trade can be made. The answer is just `initial_ones`.

Let's refine the logic for a single query `[l, r]`:
1.  Construct `t = '1' + s[l...r] + '1'`.
2.  Find all blocks of '1's surrounded by '0's in `t`. Let their lengths be `L1_1, L1_2, ...`. If none exist, no trade is possible.
3.  Find all blocks of '0's surrounded by '1's in `t`. Let their lengths be `L0_1, L0_2, ...`. If none exist, no trade is possible.
4.  If both types of blocks exist, the best trade is to sell the shortest possible block of '1's (length `min(L1_i)`) and buy the longest possible block of '0's (length `max(L0_j)`).
5.  The gain is `max(L0_j) - min(L1_i)`.
6.  The initial number of '1's is the count of '1's in `s[l...r]`.
7.  The final answer is `count('1' in s[l...r]) + max(0, max(L0_j) - min(L1_i))`.

**The Challenge:**
The constraints are `n <= 10^5` and `queries.length <= 10^5`. A naive approach of processing each query by building the augmented string and scanning it would be `O(Q * n)`, which is too slow (`10^5 * 10^5 = 10^{10}`). We need a more efficient way to find `initial_ones`, `min_len_1`, and `max_len_0` for each query range `[l, r]`.

**Preprocessing `s`:**

Let's analyze the patterns we are looking for:
- `01...10`: A block of '1's surrounded by '0's. In the original string `s`, this corresponds to a block of '1's at `s[i...j]` where `s[i-1] == '0'` and `s[j+1] == '0'`.
- `10...01`: A block of '0's surrounded by '1's. In the original string `s`, this corresponds to a block of '0's at `s[i...j]` where `s[i-1] == '1'` and `s[j+1] == '1'`.

The augmentation `t = '1' + s[l...r] + '1'` complicates things.
- A block of '1's starting at `s[l]` might be surrounded by `t[0] = '1'` and `s[l-1]` (if `l>0`). No, the augmented string is `t = '1' + s[l...r] + '1'`. The character before `s[l]` is `t[0] = '1'`. The character after `s[r]` is `t[len(t)-1] = '1'`.
- Let `sub = s[l...r]`. `t` has length `r-l+1+2`.
- The character before `sub[0]` (i.e., `s[l]`) is the augmented '1'.
- The character after `sub[r-l]` (i.e., `s[r]`) is the augmented '1'.

Let's analyze the blocks within the query range `[l, r]`.
A block can be:
1.  **Fully contained:** The block and its surrounding characters are all within `s[l...r]`.
2.  **Touching the left boundary:** The block starts at `s[l]`. Its left neighbor is the augmented '1'.
3.  **Touching the right boundary:** The block ends at `s[r]`. Its right neighbor is the augmented '1'.
4.  **Spanning the whole range:** The block is `s[l...r]`. Its neighbors are the augmented '1's.

Let's pre-calculate information about blocks in the original string `s`.
We can parse `s` and identify all contiguous blocks of '0's and '1's.
Example: `s = "11001011100"`
Blocks:
- `11` at `[0,1]`
- `00` at `[2,3]`
- `1` at `[4,4]`
- `0` at `[5,5]`
- `111` at `[6,8]`
- `00` at `[9,10]`

For each block, we can store its type ('0' or '1'), start index, end index, and length.
Let's also identify the "surrounded" blocks.
- A block of '1's at `s[i...j]` is surrounded by '0's if `i>0`, `j<n-1`, `s[i-1]=='0'`, and `s[j+1]=='0'`.
- A block of '0's at `s[i...j]` is surrounded by '1's if `i>0`, `j<n-1`, `s[i-1]=='1'`, and `s[j+1]=='1'`.

Let's create two lists:
- `sell_blocks`: list of `(length, start, end)` for blocks of '1's surrounded by '0's in `s`.
- `buy_blocks`: list of `(length, start, end)` for blocks of '0's surrounded by '1's in `s`.

Now, for a query `[l, r]`, we need to find `min_len_1` and `max_len_0` within the augmented substring `t`.

**Finding `min_len_1` (shortest sellable '1' block):**
A block of '1's in `t` is sellable if it's surrounded by '0's.
Let `sub = s[l...r]`.
The '0's can come from `sub` itself.
- **Case 1: Fully contained `01...10` pattern.** This corresponds to a `sell_block` from our precomputed list that is fully contained in `[l, r]`. We need to find the minimum length among all such blocks. This is a range minimum query (RMQ) on the lengths of `sell_blocks`.
- **Case 2: Boundary effects.** The augmented '1's are neighbors. They can't create a `0...0` environment. So, the boundaries don't help create sellable '1' blocks. A block of '1's at `s[l...j]` has an augmented '1' to its left. A block at `s[i...r]` has an augmented '1' to its right. These are not surrounded by '0's.
So, `min_len_1` for `s[l...r]` is simply the minimum length of a `sell_block` that is fully contained in the range `[l, r]`.

**Finding `max_len_0` (longest buyable '0' block):**
A block of '0's in `t` is buyable if it's surrounded by '1's.
The '1's can come from `sub` or the augmented boundaries.
- **Case 1: Fully contained `10...01` pattern.** This corresponds to a `buy_block` from our precomputed list that is fully contained in `[l, r]`. We need the maximum length among these. This is a range maximum query (RMaxQ) on the lengths of `buy_blocks`.
- **Case 2: Boundary effects.**
    - A block of '0's starting at `s[l]`: `s[l...j] = '0...0'`. In `t`, this is preceded by the augmented '1'. If `s[j+1] == '1'` (and `j < r`), then this block `s[l...j]` is buyable.
    - A block of '0's ending at `s[r]`: `s[i...r] = '0...0'`. In `t`, this is followed by the augmented '1'. If `s[i-1] == '1'` (and `i > l`), then this block `s[i...r]` is buyable.
    - The entire substring `s[l...r]` is '0's. In `t`, this is `'1'0...0'1'`. This block is buyable. Its length is `r - l + 1`.

So, for a query `[l, r]`, `max_len_0` is the maximum of:
1.  `RMaxQ` on `buy_blocks` fully within `[l, r]`.
2.  Length of the prefix of '0's in `s[l...r]` if it's followed by a '1' within `s[l...r]`.
3.  Length of the suffix of '0's in `s[l...r]` if it's preceded by a '1' within `s[l...r]`.
4.  `r - l + 1` if `s[l...r]` consists only of '0's.

2.  `P1`: prefix sums of '1's. `P1[i+1] = P1[i] + (1 if s[i]=='1' else 0)`.

       ii. `max_l0_internal_results[q_idx] = ST_max.query(l, r)`.
